    A* from the ground up

    Learn the A* search algorithm

    A* finds a minimum-cost route through a weighted graph. It combines the cost already paid with an estimate of the cost still remaining, so it can search toward the goal without ignoring cheaper alternatives.

    1. Represent the problem as a graph

    A* does not move through empty space directly. It searches a collection of connected positions:

    Node
    A position the search can visit. In AStarLab, the numbered circles are nodes.
    Edge
    An allowed move between two nodes. The line connecting them represents that move.
    Cost
    The number shown on an edge. A* minimizes the sum of these costs, not the number of edges.
    Start and goal
    The green node is where the route begins; the red node is the destination.

    Obstacles disable every edge they intersect. Moving an obstacle therefore changes the graph that A* searches.

    2. Understand the three scores

    For every candidate node n, A* calculates:

    f(n) = g(n) + h(n)
    g(n)

    The exact cost of the cheapest route currently known from the start to n.

    h(n)

    A heuristic estimate of the remaining cost from n to the goal.

    f(n)

    The estimated total route cost if the search continues through n.

    AStarLab uses straight-line distance divided by 10 and rounded down for h. A smaller f makes a node more promising, so it receives higher priority.

    3. Follow the search loop

    1. Set the start node's g to 0 and place it in the open set, a priority queue ordered by f.
    2. Remove the open node with the smallest f. This becomes the current node.
    3. If current is the goal, follow its stored parent links backward to reconstruct the path.
    4. Otherwise, inspect each reachable neighbor and calculate tentativeG = g(current) + edgeCost.
    5. If that value is cheaper than the neighbor's known g, store the better g, calculate its h and f, and set current as its parent.
    6. Move current to the closed set and repeat. Closed nodes have already been expanded.

    If the open set becomes empty before reaching the goal, no route exists through the enabled edges.

    4. Work through one neighbor update

    Assume the current node has g = 12, the edge to a neighbor costs 5, and that neighbor previously had g = 21.

    tentativeG = 12 + 5 = 17

    Because 17 < 21, A* found a cheaper way to the neighbor. It changes the neighbor's g to 17 and records current as its parent. If the neighbor's h = 8, its new priority is f = 17 + 8 = 25.

    5. Why the heuristic matters

    The heuristic guides the search. A useful heuristic reduces unnecessary exploration, but it must be trustworthy:

    • h(n) = 0 makes A* behave like Dijkstra's algorithm. It remains optimal but usually explores more nodes.
    • An admissible heuristic never overestimates the real remaining cost.
    • A consistent heuristic also obeys the triangle inequality across every edge, so a closed node never needs to be reopened.
    • An overestimating heuristic may search faster, but it can miss the cheapest route.

    AStarLab's geometric heuristic is admissible and consistent with its distance-based positive edge costs.

    6. When A* is optimal

    On a finite graph with non-negative edge costs, A* is complete: it finds a route whenever one exists. With an admissible heuristic—and a consistent heuristic for this closed-set implementation—the returned route has the smallest possible total cost.

    The final highlighted route is reconstructed from parent links. Those links remember which previous node produced each node's cheapest known g.
